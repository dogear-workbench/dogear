# Doc Sync

文档同步检查工作流。**只在改动达到"值得记录"门槛时才动手改**——大多数小修改不需要更新文档。

## 决策树

### Step 1 · 这次改动值得更新文档吗？

**值得更新**（继续 Step 2）：
- 新增了文件：page / component / store / service / tipc 路由 / Agent 工具
- 删除或重命名了已在 `dogear/codebase-map/` 地图中提及的文件
- 拆分或合并了大模块（影响代码地图的归类）

**不值得更新**（直接结束）：
- bug 修复、样式调整、文案修改
- 在已有文件内添加函数/方法（不改变文件职责）
- 重构内部实现但对外接口不变
- 测试代码、临时调试代码

### Step 2 · 执行

Read `dogear/codebase-map/index.md`，按功能词路由定位目标功能文件，精准编辑该文件中需要改动的行：
- 新文件是否需要加入对应功能文件？（只列**有结构意义**的文件：service / store / 主要组件 / 路由 handler，辅助 utility 不必）
- 删除/重命名的文件是否清理了对应行？
- 模块归类是否还准确？（条目只在主功能文件出现，次要相关文件留一行指针）

条目格式：`路径` — 一句话职责，一行内说清，不写实现细节。硬约束（唯一数据源 / 不许绕过的通道 / 易错语义）写进该功能文件尾部 `## 注意` 区，不写进条目行。

每改一处都要**精准编辑**——不要顺手重写整段，只动需要动的行。

### Step 3 · 不要做的事

- ❌ 不要为了"完整性"把每个新增文件都列入。只列有结构意义的文件。
- ❌ 不要重写整段，只动需要改的行。

## 自检

完成后用一句话向用户汇报：改了哪些文档、哪些**故意没改**及原因。如果决定不更新任何文档，直接说"本次改动不触达文档层"，不要默默跳过。
