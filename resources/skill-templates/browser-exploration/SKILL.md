# 浏览器探索 Skill

## 双通道定位与选择

两条通道工具对等（导航 / 观察 / 点击填写 / 读文章 / 截图），差异在宿主与协作模式：

- 内嵌通道（dogear__browser__*）：Dogear 自带的隔离浏览器，无人值守可用。适合公开网页调研、搜索与文章快档、需要环境隔离的自动化任务。
- 扩展通道（dogear__extension__*）：作用于用户真实浏览器的 Dogear 分组标签页，自带登录态，用户可见、随时可亲自介入。适合登录态站点、需要用户在场协作（人工验证、确认提交、亲眼确认页面）的任务。

选择原则：

- 站点需登录态、或需要用户看到 / 参与页面 → 扩展通道优先；公开内容、无人值守、隔离环境 → 内嵌通道优先。
- 一个任务固定一条通道做完，不要来回切换；换通道前先想清楚是否真的必要。
- 节奏预算按会话计、双通道共用：预算耗尽或风控熔断时换通道同样被拒，正确动作是停止并如实告知用户，不要换通道规避。
- 扩展通道同一时间仅一个会话可用（被占用直接报错，不排队）；并行调研时浏览器子会话请串行派遣。

## 通用探索循环

通道无关，两条通道同样适用：

- 行动前先确认页面状态：先 observe_page 获取当前页面事实（SPA 页面可先用 read_state 看顶层概要），不要凭记忆或假设直接操作。
- 每次下钻带明确假设；页面与预期不符时先回到已知页面再继续，不把偏离当失败上报。
- 读取失败不白跑：读取类工具失败时返回附失败原因与页面现状（快档失败时页面通常保留在原处并附位置），按返回指引改用原子工具（observe_page / find / read_text）从当前状态接续，不要盲目重新导航。
- 元素引用（ref）是代际的：页面导航或路由变化后旧 ref 全部失效，操作新页面前先重新 observe_page / find。
- 遇到人工介入信号（登录墙、人机验证、密码 / 提交类拦截）即停并告知用户，不要轮询重试。两条通道的继续机制不同：内嵌通道产生「等待人工」卡片，用户在浏览器面板完成后点「完成后继续」唤醒会话；扩展通道提交类点击弹确认卡（批准后自动执行），密码与登录验证由用户在自己的浏览器直接动手，完成后重新 observe_page 感知页面变化。一律以工具返回的指引为准。

## 站点档案与访问策略

- 到达新站点先看档案与策略：工具返回尾部出现「站点档案 / 访问策略」指针时，先调本通道的 site_knowledge / site_policy 再开始操作（两条通道共用同一份档案，但工具名随通道前缀，勿混用）。有已知地图就不必盲探。
- 节奏延迟、操作预算、危险信号清单由策略层强制执行，数值以 site_policy 返回为准：调用变慢或被拒是保护不是故障，耐心等待或停下，不要绕过、不要硬闯重试。
- 探索中发现可复用的新知识（状态路径、直链拼法、页面怪癖）用本通道 site_finding 沉淀到站点档案发现区，供后续会话复用；交付前记得写。

## 何时停与交付

- 同一页面连续 3 次探索失败即停，汇报已发现的内容与卡点。
- 出现滑块 / 验证码即停：不规避、不绕过、不加随机延迟硬闯。
- 交付：内嵌通道调研完成后用 present 把关键页面呈现给用户（页面即产物），再在回复里给结论；扩展通道页面本就在用户浏览器中，明确告诉用户看哪个标签页即可。
