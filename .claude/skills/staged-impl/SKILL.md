# Staged Implementation

把大任务拆成独立可落盘的步骤，规划与执行分离，通过文档接力避免上下文累积导致的精度丢失。

## 何时用 / 何时不用

**用**：
- 改动跨 ≥3 个文件且步骤间有依赖关系
- 需要跨会话续做（一次做不完）
- 涉及架构层面变更（store / service / IPC 路由 / Agent 工具）

**不用**：
- 单文件改一两处
- bug 修复（用 systematic-debugging skill）
- 探索类任务（用子代理直接做，参考全局 CLAUDE.md「子代理使用」）

## 文档拓扑

```
docs/plans/YYYY-MM/YYYY-MM-DD/<feature-name>/
  plan.md           # 总览 + 步骤索引
  step1-<short>.md  # 单个步骤的详细文档
  step2-<short>.md
  ...
```

不要把所有步骤揉进一个文件——执行时只读当前 step + 必要前置接力棒，避免整份计划压上下文。

## plan.md 模板

```markdown
# <Feature Name> 实施计划

**目标**：（一句话说清要达成什么）

**架构思路**：（2-3 句说做法，排除了哪些选项及原因）

**涉及模块**：（关键文件 / store / service / IPC 路由）

## 步骤索引

- [ ] [Step 1: <标题>](./step1-<short>.md) — 一句话说做什么
- [ ] [Step 2: <标题>](./step2-<short>.md) — 一句话说做什么
- [ ] [Step 3: <标题>](./step3-<short>.md) — 一句话说做什么

## 全局决策

（跨步骤都要遵守的约定：命名、数据格式、错误处理等）
```

## stepN.md 模板

```markdown
---
step: N
title: <短标题>
status: pending | in_progress | done
---

## 目标
（这一步要达成什么，一句话）

## 依赖上下文（接力棒输入）
- 前置 step 产出：[step{N-1}.md] 改了 XXX，关键签名是 YYY
- 当前关键文件状态：`stores/xxx-store.ts` 的 setXXX 签名是 `(id: string) => void`
- 关键决策回顾：之所以这样设计是因为 ZZZ（避免下个 step 又问一遍）

## 计划改动
- [ ] `path/to/file.ts:42` 加 xxx 方法
- [ ] `path/to/other.ts` 调用点切换

## 实施回填（做完后填）

### 实际改动
- 与计划差异：（新发现的边界、调整的设计）
- 改动文件清单：`a.ts` / `b.ts` / `c.ts`

### 给下一步的接力棒
- 关键签名 / 数据结构：`xxx(): YYY`
- 下个 step 该从哪里继续：（具体的入口点）
- 待办或已知限制：（这一步没做完的、暂时不处理的）
```

## 工作流

### 规划阶段（write）

1. 跟用户对齐目标和架构思路（拿不准先问，不要带着 50% 把握就开始写文档）
2. 拆分步骤：每个 step 是「能独立验证完成」的单元，不是「2-5 分钟微动作」
3. 创建目录 `docs/plans/YYYY-MM/YYYY-MM-DD/<feat>/`
4. 写 `plan.md` 总览 + 每个 `stepN-<short>.md`（依赖上下文留空，等执行时填）

### 执行阶段（execute）

**关键纪律**：执行 step N 时，上下文里只放：
- 当前 `stepN.md` 全文
- `plan.md` 的「全局决策」一节
- 必要的前置 step 的「给下一步的接力棒」一节（按需，不要全读）

不要把整份 plan 都拉进上下文。

每个 step 完成后：
1. 在 `stepN.md` 的「实施回填」一节写：实际改动、接力棒
2. 在 `plan.md` 的步骤索引把 `[ ]` 改 `[x]`
3. 如果是跨会话续做，可以这里就结束，下次会话从下一个 step 开始

### 完成阶段

所有 step 都打勾后：
- 在 `plan.md` 末尾加「## 完成总结」：实际改动汇总、与原计划的偏差
- 不强制提 PR / merge（dogear 是单人项目，自己决定）

## 不做的事

- 不强制 TDD（项目偏好不写单测）
- 不要让 plan 文档承载实施过程的所有上下文（那样还不如不分步骤）
- 不要 step 之间的接力棒只写「完成」二字——必须写关键签名/决策，否则下次会话冷启动接不上
- 不要在 step 文档里复制大段源码——给文件路径和行号引用即可
