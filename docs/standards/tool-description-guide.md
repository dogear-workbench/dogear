# 工具描述编写规范

Dogear 自定义工具的 `description` 字段是模型唯一能看到的工具说明（`shortDescription` 不发给模型）。本规范定义描述该写什么、不该写什么。

## 三要素

每个工具描述由三部分构成：**做什么、何时做、不做什么**。

### 做什么（能力）

一句话说清这个工具执行什么操作、产出什么结果。

### 何时做（场景）

用"仅用于…时"收窄到唯一适用场景。场景越精确，agent 越不会在不该用的时候选这个工具。

### 不做什么（排除）

**如果"何时做"已经精确到唯一场景，这条隐含成立，不需要显式写。**

只有当历史经验表明 agent 容易误用时才考虑补强。补强方式仍然是通过调整"何时做"的措辞来覆盖（正面限定），而不是加否定式排除。

| 方式 | 句式 | 评价 |
|------|------|------|
| 正面限定 | "仅用于需要向同组其他会话传递文件时" | 好——收窄场景，自然排除其他 |
| 否定排除 | "不要用于工作区项目文件" | 差——只说了不能做什么，没说什么能做 |

### 标准格式

```
<做什么>。仅用于<何时做>时。
```

## 不该出现在描述里的内容

| 类型 | 说明 | 该放哪 |
|------|------|--------|
| 参数名和参数语法 | `tail=N`、`range=[start,end)` | zod schema 的 `.describe()` |
| 实现细节 | dry-run 校验、回滚机制、状态机 | 不需要告诉 agent |
| 返回格式 | 字段列表、格式标记 | agent 从返回值自己解析 |
| 跨工具引用 | "请用 write 工具"、"配合 WaitForMessage" | 工具描述只说自身 |
| 使用建议 | "简短交付可以放进 SendMessage" | skill 或系统提示词 |

## 好坏对比

### SaveSharedNote

```
✗ 写入会话组共享区的文件（覆盖已有内容）。工作区项目代码/文档请用 write 工具。
  — 否定式排除 + 跨工具引用

✓ 向会话组共享区写入文件（覆盖已有内容）。仅用于需要向同组其他会话传递文件时。
```

### CreateSession

```
✗ 创建一个平级的新会话来协作处理任务。新会话与当前会话建立契约通道，可通过
  SendMessage / WaitForMessage 双向通信。outputPath 用于建议新会话把较长的交付
  内容写到共享区；简短交付可以直接放进 SendMessage 里。profile 参数用于选择…
  — 跨工具引用 + 参数说明 + 使用建议

✓ 创建一个子会话来执行独立任务，与当前会话建立双向通信通道。仅用于需要把任务委派给独立会话处理时。
```

### ListGroupFiles

```
✗ 列出当前会话组共享区的所有文件并返回内容。不要用于查看工作区项目文件。
  — 缺"何时做"，否定式排除

✓ 列出会话组共享区的所有文件并返回内容。仅用于查看同组会话放到共享区的文件时。
```

## 能力描述中的操作模式

描述"做什么"时可以隐含暗示工具支持的操作模式，但不写参数语法：

```
✓ 读指定会话的去噪原文（可尾切或区间切）。
  — "可尾切或区间切"是能力描述，agent 会去看 schema 了解怎么传

✗ 读指定会话的去噪原文。tail=N 返回后 N 条；range=[start, end) 按去噪后 index 切。
  — 参数语法混入了描述
```
