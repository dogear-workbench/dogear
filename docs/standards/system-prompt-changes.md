# 系统提示词段改动清单

配合工具描述改动，对会话协作相关的系统提示词段做合并和措辞调整。

## 当前状态

| 段 | key | 注入条件 |
|----|-----|---------|
| 会话组上下文 | group-context | 有 groupId |
| 共享区阶段总结引导 | notes-guidance | 主会话 + 有工作区 |
| 子会话交付契约 | sub-agent-contract | role='sub' |
| 主会话协作规范 + Profile 索引 | main-agent-delegation | role='main' + 有 groupId |

问题：4 个段碎得太散，前两个本质是同一件事（共享区读/写），后两个本质也是同一件事（主子协作）。

## 合并方案：两个主题

### 主题 1：会话组上下文（读 + 写合一）

合并"会话组上下文" + "共享区阶段总结引导"为一段。

**注入条件**：有 groupId 时注入（主/子都看到）

**段内容**：

```
## 当前会话组上下文

**组**：<组标题 或 未命名组（创建于 …）>

共享区是会话组内跨会话传递文件的区域。遇到不清楚的背景，先看看共享区有没有相关文件（ListGroupFiles）。
当某个阶段告一段落或上下文用量较高时，可以主动写一份阶段总结到共享区（SaveSharedNote），方便下次接续或组卡提炼。这不是强制——只在你判断有价值时做。
```

**变化**：
- 原来分两段（读给所有人、写只给主会话），合为一段
- 子会话也能看到写入说明——之前子会话看不到这段，是交付文档写错位置的诱因之一

### 主题 2：主子会话通讯与操作

注入条件互斥（主/子），物理上还是两段，逻辑归一类。

#### 主会话版

**注入条件**：role='main' + 有 groupId

```
## 主会话与子会话协作规范

用 CreateSession 派遣子会话后，必须紧接着调用 WaitForMessage 挂起等待，不要在创建后直接结束本轮——否则子会话的交付无人接收。

## 可用的子会话 Profile

派遣子会话时可通过 profile 参数选择合适的 Profile（不指定时用「默认」）：
| Profile | 说明 |
|---------|------|
| 默认 | … |
```

**变化**：基本不动。

#### 子会话版

**注入条件**：role='sub'

```
## 你是一个被派遣的子会话

**任务**：${task}

**交付路径**：${outputPath}（把完整交付内容写到共享区这个路径，SendMessage 里只放摘要通知）

**交付流程**：完成后用 SendMessage 向派出你的会话交付结果（delivery: true）；有歧义时先反问，不要瞎猜。你不能派遣孙子会话。
```

**变化**：
- 交付路径从"建议交付路径"改为"交付路径"
- 去掉"内容较长时先用 SaveSharedNote 写进去"的条件判断
- 改为无条件的"把完整交付内容写到共享区这个路径"
