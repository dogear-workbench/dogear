# 话题级归档与删除设计

**背景**：当前产品内部已经按会话组聚合展示，但归档仍按单会话存储和渲染。`Conversation.archivedAt` 会让话题保留不可见会话；空话题清理又把归档会话计为存活，最终留下无法删除的空组。组卡片的“删除”文案与后端拒绝删除非空组的行为也不一致。

**目标**：

- 用户界面将“会话组”统一称为“话题”。
- 归档的唯一粒度是话题；归档话题保留其会话、摘要、背景、共享文件、文件夹引用和智能分类引用。
- 归档话题从正常的手动、智能、时间视图排除，在独立折叠区按话题展示。
- 归档话题内的会话只读；恢复话题后才可继续发送或新建会话。
- 删除单条会话始终硬删除；删掉话题的最后一条会话时自动彻底删除话题。
- 删除话题时级联删除所有会话及关联存储。
- 升级时永久清理全部旧单会话归档及由此遗留的空话题，不保留旧归档内容。

**架构**：

内部继续使用稳定的 `groupId`、`groups.json` 与 `groups/<groupId>/` 路径，避免无价值的 ID 和目录迁移；仅在前端文案、确认框和新接口语义中使用“话题”。`Group` 增加 `archivedAt?: number`，由 `groups.json` 的版本化迁移管理。归档状态只存在于 Group，移除产品功能中的 `Conversation.archivedAt/archiveReason` 单会话归档语义及相应 IPC。

新增话题级接口：归档、恢复、列出已归档话题，以及按话题硬删除。归档列表使用一个后端组合视图返回话题及其会话，避免把归档会话混入活跃 `conversation-store` 后再由多个前端视图各自过滤。普通会话列表只返回属于活跃话题的会话；`getById` 返回所属话题是否归档，以便聊天页强制只读。

归档运行中的话题时，确认框明确提示会停止其中运行中的会话；确认后先关闭运行时，再写入话题归档状态。已归档话题拒绝新建会话、attach runtime 和发送消息，防止后台继续写入后重新出现在活跃视图。

**模块边界**：

- `types/group.ts`、`electron/main/types.ts`、`electron/main/services/group-service.ts`：话题归档字段、版本迁移、活跃/归档列表与状态写入。
- `electron/main/tipc/group.ts`：话题归档、恢复、列表和真正的级联删除 RPC。
- `electron/main/tipc/conversations.ts`、`conversation-service.ts`：删除单会话只走硬删除；活跃列表过滤已归档话题；创建和运行时入口校验话题活跃状态。
- 新的共享话题生命周期协调层：集中执行会话文件、运行时、用量、对话索引、树、智能分类及 `groups/<groupId>/` 的清理，供“删除话题”和“最后会话删除”共同复用。
- `stores/group-store.ts`、`stores/conversation-store.ts`：活跃话题与归档话题分离加载；移除“有 session 就归档”的删除分流。
- `components/ConversationList.tsx`、`conversation-list/ArchiveSection.tsx`、`group-list/GroupCard.tsx`、`ConversationRow.tsx`、`AgentChat.tsx`：话题文案、话题归档区、只读模式、组级恢复/永久删除、删除确认语义。
- `components/ArchivePanel.tsx`、`ui-store.ts`、旧单会话归档 IPC：删除无效入口与状态。
- `conversation-tree-service.ts`、`memory/smart-category-store.ts`、`memory/group-digest-store.ts`：仅在彻底删除话题时清理引用和组目录；归档时一律保留。

**数据流**：

1. 用户从话题菜单选择归档。前端确认运行中会话的停止影响，调用话题归档 RPC。
2. 后端停止该话题的活跃运行时，写入 `Group.archivedAt`，通知前端刷新活跃列表和话题列表。
3. 活跃视图只使用未归档话题；归档区懒加载归档话题及其会话。会话点击进入只读聊天页；恢复操作清除 `archivedAt`，原有文件夹和分类引用无需重建。
4. 删除单会话先删除 Harness 会话文件和用量，再删索引；若话题无剩余会话，调用同一生命周期协调层彻底删除话题。
5. 删除话题逐会话执行同样的硬删除，成功后删除组记录、树引用、智能分类引用和整个组目录。
6. 启动迁移扫描所有 `archivedAt` 会话，按硬删除规则清理其索引、Harness/旧 SDK 历史和用量；随后清理无会话话题及其关联引用。迁移标记只在全量扫描完成后写入，重复执行安全。

**错误处理 / 边界情况**：

- 话题级删除先关闭运行时并删除会话持久化文件；任一会话文件删除失败时返回明确错误并保留尚未删除的索引，后续操作可幂等重试。
- 已归档、已删除、空话题等重复操作必须无副作用。
- 归档只隐藏话题，不删除树和分类引用；永久删除才移除全部引用。
- 迁移删除的是所有历史单会话归档，不区分手动归档和旧 SDK 迁移归档，以保证归档粒度唯一。
- 只有归档话题时存在的会话可只读浏览；不能因归档状态缺失而 attach、继续发送或创建子会话。

**验收标准**：

- 活跃会话删除后不产生任何单会话归档记录。
- 归档和恢复只作用于完整话题，恢复后回到原文件夹和智能分类。
- 活跃/归档话题均可正确显示会话数；正常视图无空话题。
- 删除最后一条会话、删除完整话题、迁移清理旧归档后，索引、会话文件、用量、树、分类、摘要/背景/共享目录均无孤儿引用。
- 已归档话题不能发送、创建、附着运行时；恢复后可正常继续。

**未决问题**：无。
