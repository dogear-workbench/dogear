## 一、愿景：从"被动记忆"到"参谋"

原路线图里的里程碑 2 是一个**被动的做梦系统**——会话关闭时在后台默默存几条事实。本轮讨论把它的格局彻底打开了：

> 我想要的不是一个被动记忆，而是可以与我一起、他也能时常启发我的 agent。帮我整理会话、分类、追踪哪些思路落实了/搁置了/没执行，比如 dogear，我们可以一起把这个产品迭代下去——git 全是零零碎碎的，但通过整理、通过我们的会话能提炼更多东西出来。

所以里程碑 2 的真正目标是：**把"记忆"从仓库升级成"参谋"**。它能

1. **提炼会话**——从零散对话里综合归纳，不只是记事实
2. **分类整理**——为对话/主题归类（复用里程碑 1 的工作区主题）
3. **追踪思路生命周期**——哪些想法落实了 / 搁置了 / 没执行（核心诉求，目前无任何系统在做）
4. **主动启发**——反过来推着我走，"上次聊到 X 还没做，要不要捡起来"
5. **从零碎里提炼叙事**——把零散 commit + 会话串成"我们在往哪个方向迭代"

### 为什么 SDK 自带的 auto-memory 不够

现状是**两套记忆已并存**（见里程碑 1 文档第 572 行预留的开放问题，现已成事实）：

| 系统 | 位置 | 粒度 | 工具 | 性质 |
|------|------|------|------|------|
| **A. dogear-memory**（里程碑 1 自建） | `<工作区>/.dogear/memory/`（core-profile + topics + index.json） | 工作区级·主题 | `mcp__dogear-memory__{Recall/Save/Forget}` | 手动，被动 |
| **B. SDK auto-memory** | `~/AppData/Roaming/dogear/.dogear/conversations/projects/C--dogear/memory/` | 全局·画像 | SDK 文件机制（MEMORY.md + 分类 md） | 自动，但只做被动存取 |

SDK auto-memory（系统 B）只做被动存取——不综合、不追踪状态、不主动启发。里程碑 2 要补的正是这三件 B 不做的事，建立在**系统 A（工作区级 dogear-memory）**之上。系统 B 维持现状不动；本里程碑不依赖它，也不改它。

## 二、架构全景：三级流水线 + 仪表盘

核心洞察：**会话 JSONL 是永久真相源，不复制、不动它**；记忆层只存"提炼后的产物"，要看细节顺着回溯链按需读原文。

```
原始会话 JSONL（永久真相源，不动它）
        │
   ① 脚本去噪（零 AI 成本，约 30x 压缩）
        │  只留"用户发言 + 助手文字"，丢工具结果体 / envelope；每段保留消息 uuid
        ▼
   干净逐字稿（约 3.5 万 token / 会话）
        │
   ② 后台提炼（headless query + 可编辑 prompt 模板，不是 skill）
        │  脏检查触发；归纳"说了几件事 + 简要" + 抓细(想法/注意/决策) + 出处 uuid
        ▼
   摘要卡（.dogear/memory/digests/，主题归类复用里程碑 1）
        │                       └→ 设置页 MemoryTab 加"会话摘要"巡检视图
        │
   ③ 跨会话综合（skill，一功能一个，可迭代）—— 复盘 / 叙事 / 启发
        │  只读 ② 攒下的小摘要堆（便宜），不重读原始会话
        │  将来也做成 agent 工具（聊天中途可调）
        ▼
   首页仪表盘（升级 EmptyFocusState，开软件就看见）
        ├─ 参谋区：最近完成 / 搁置的思路 / 下一步建议（③ 产出）
        └─ 我的区：草稿 / 粘贴的信息 / 速记（用户自己的）

   回溯链：任何一条 →(会话id, uuid)→ 按需读那行 JSONL 看原话
```

每一层都便宜、都可独立验证：① 单独跑出干净稿、② 单独产卡、③ 只吃小摘要、仪表盘只读现成产物。

## 三、本轮已拍定的关键设计决策

这些是本次讨论的结论，实现时遵守，不再反复：

1. **token 策略：脚本去噪，不全量喂 AI。**
   实测一个 2.3MB 会话里，纯讨论（用户+助手文字）只占 2.6%，其余 97% 是工具结果体 + envelope 副本。全量喂 AI 不仅贵 30 倍，还会用工具噪音淹没信号、拉低提炼质量。

2. **"工具"不是噪音，"工具的中间材料"才是。**
   - 留：用户发言、助手文字回复（这是"我们的讨论"）。
   - 对 vibe-coding 工作区，工具执行细节连动作都可省（思路在讨论时已定，工具只是落地）。起步以"用户+助手文字"为信号；工具动作骨架作为可选增强，按需再加。
   - 丢：工具结果正文（Read 文件全文、Grep 整页、Bash 长日志）、envelope（cwd/usage/uuid/toolUseResult 副本）、斜杠命令与本地命令系统行（`<command-name>` / `<local-command-stdout>` / `<system-reminder>` 等）。

3. **②是固定流水线 → 用可编辑 prompt 模板；③是需判断的流程 → 用 skill。**
   不给 ② 套 skill 机制（headless、任务固定、无"按需激活"场景，套 skill 是过度工程）。不把 ③ 省成纯提示词（judgment 重、多功能、要被主动唤起，提示词撑不住）。③ 一个功能一个 skill，可迭代（同 article-parser 的自进化套路）。

4. **②的触发 = 一个脏检查机制，三个触发点；不做独立服务。**
   - 脏检查条件：`摘要不存在` 或 `摘要时间 ≠ 会话最后更新时间`。
   - 三个触发点：开软件扫一遍 / 晚上定时扫（仅当软件开着）/ 手动关会话只扫这一个。
   - 软件关闭即停，不留后台守护进程。
   - 存量 ~30 个会话因"无摘要"天然命中脏检查，开软件扫一遍即完成 backfill，无需单独补漏逻辑。
   - 没聊完的会话无所谓：下次变脏再重提炼，提示词里让模型对比"旧摘要 vs 新内容"决定替换/重写。

5. **回溯链几乎零成本。**
   每条 JSONL 消息都带稳定 `uuid` + `timestamp`。链条就是 `(会话id, uuid)` 一对，要看原文按需重读那一行，不搭额外索引。卡级回溯（frontmatter 已有会话id）免费；条目级回溯让 ② 给每条想法/决策顺手带上出处 uuid。

6. **②的提炼模型可在记忆设置里勾选。**
   不硬编码。在 MemoryTab 加一个模型选择，从已配置的 model profile 里勾一个用于后台提炼（建议默认选便宜模型，用户可改）。

7. **记忆/仪表盘每工作区独立。**
   沿用里程碑 1 的 `<工作区>/.dogear/memory/`。仪表盘是"进某工作区看该工作区的参谋"。全局总览层后续再说。

8. **"想法状态追踪（落实/搁置/放弃）"本轮挂起。**
   它依赖 ③ 真正跑起来、积累真实数据后才知道怎么判，现在硬设计是拍脑袋。先把流程走通，留到 Phase D 迭代。

## 四、阶段划分

按"每阶段产出可独立使用的功能"切分。依赖关系：A → B → C(参谋区)；C(草稿区) 与 D 独立。各阶段开工时再单独写详细实现方案。

### Phase A：提炼地基（① + ② + 巡检）

**目标**：把会话自动提炼成摘要卡，存量 + 增量都覆盖。
**独立价值**：在设置页能浏览"每个会话讲了什么、冒出哪些想法"，即便 ③/仪表盘还没做也有用。

- **A1 · 清洗脚本（①）**：解析 JSONL → 干净逐字稿。去噪规则见决策 2，保留每段 uuid。零 AI、确定性、可单独跑验证。
- **A2 · 提炼任务（②）**：脏检查（决策 4）+ 三触发点接入 + headless query + 可编辑 prompt 模板 + 摘要卡落盘（`.dogear/memory/digests/`）+ 主题归类复用里程碑 1 + 提炼模型读自记忆设置（决策 6）。
- **A3 · 设置页巡检视图**：MemoryTab 新增"会话摘要"列表（点开看卡、带回溯链接跳原文）+ 提炼模型勾选 UI。

### Phase B：参谋综合（③ skills）

**目标**：读 A 攒下的摘要卡堆，做跨会话的复盘/叙事/启发。
**独立价值**：能主动让 agent"帮我复盘 dogear 最近思路 / 串一下我们做了什么"。

- **B1 · 第一个 skill**（建议先做"产品叙事/复盘"：把零碎 commit + 摘要串成"我们在往哪走 + 哪些没落实"）。
- **B2 · 迭代/追加 skill**（启发、其他功能；一功能一个，按需加）。
- 约束：③ 只读摘要卡（小、便宜），不重读原始 JSONL。

### Phase C：首页仪表盘

**目标**：升级 `EmptyFocusState`，开软件/无聚焦会话时呈现一个仪表盘。
**独立价值**：参谋产物 + 个人速记都有了固定的"开机即见"的家。

- **C1 · 仪表盘骨架**：替换/扩展 `EmptyFocusState`，分"参谋区 / 我的区"两块。
- **C2 · 参谋区**：接 B 的产出（最近完成 / 搁置的思路 / 下一步建议），可忽略、不打断。
- **C3 · 草稿/粘贴速记区**：与记忆无关的个人速记板（草稿、粘贴信息）。本轮一起做，看效果。

### Phase D：后续/挂起（有真实数据后再迭代）

- **D1 · 想法状态台账**：跨会话把同一想法串起来，推断落实/搁置/放弃（决策 8）。
- **D2 · ③ 工具化**：把复盘/召回做成 agent 工具，聊天中途可调（用户判断："后面做好了之后做成工具那种"）。
- **D3 · 全局记忆层**：跨工作区的画像/总览（决策 7 的"全局后续再说"）。

## 五、跨阶段约束

- 不做独立后台服务（决策 4）；不切换 agent 框架；不引入向量库/embedding（关键词 + 时间窗够用，沿用里程碑 1）。
- 不复制原始会话进记忆层——只存提炼产物 + 回溯指针。
- 单用户自用定位：不搞权限/审核/confidence score，信任用户在设置页巡检。
- 文件 IO 沿用 `safe-json` 模式；IPC 走 tipc；新增文件遵守 <300 行拆分约定。
- 系统 B（SDK auto-memory）维持现状，本里程碑不依赖、不修改。
