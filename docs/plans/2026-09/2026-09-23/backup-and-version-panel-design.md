# 应用数据备份与版本面板 设计

**日期**：2026-09-23
**背景**：双层 git（影子快照安全网 + 用户仓库正式历史）已上线。首轮真人体验发现文件历史面板两处缺陷；应用数据（笔记/会话/记忆/任务）无任何备份保护；用户希望在数据中心看到版本相关功能全貌并自主管理备份。

**目标**：
1. 修复文件历史面板两处体验问题（右侧详情头 + diff 折叠）
2. 应用数据备份机制：数据分类展示，每类独立开关与频率（用户可配）+ 手动立即备份 + 可恢复——策略不写死
3. 数据中心新增「版本与备份」区块，三层状态（用户仓库 / 影子安全网 / 备份）一目了然

## 既定决策（本轮讨论拍板，不改动）

- **影子仓库保持全量快照不动**：项目 git（拍板提交的时刻）与影子快照（每次写操作后的即时点）是正交的两层；「agent 改坏已跟踪文件但未 commit」只能靠影子救回；git 内容寻址使全量快照的增量成本仅为变化文件，无需按「项目 git 是否管理」去重排除
- **应用数据不进任何 git / 影子仓库**：会话 jsonl 每条消息追加，挂快照触发器仓库会爆炸；笔记中间版本无价值——个人数据要「灾难可找回」不要「细粒度回溯」，走备份制（zip 轮换）
- **settings.json / logs 不进备份**：含 API Key 等敏感信息
- **GitHub 式整体版本视图本轮不做**（另议）；非 git 工作区不自动 `git init`

## 备份机制

### 数据分类（每类独立配置）

| 分类 | 范围 | 默认（可改） |
|---|---|---|
| 笔记与话题组 | `workspaces/<id>/notes` `groups` `dashboard.md` | 开 · 每天 |
| 记忆 | `workspaces/<id>/memory` + 全局 `.dogear/memory` | 开 · 每天 |
| 任务 | `.dogear/tasks.json` | 开 · 每天 |
| 会话 | `workspaces/<id>/sessions`（大头 ~239M） | 开 · 每月 |
| 设置与日志 | settings.json / logs / run-history 等 | **不出现在可备列表** |

- 频率选项：每天 / 每周 / 每月 / 仅手动
- 保留份数：可配，默认 10（每类独立轮换）
- 存储位置：`.dogear/backups/<workspaceId|global>/<分类>-<YYYYMMDD-HHmmss>.zip`
- 触发：**backup-service 内建轻量调度**（应用启动时检查 + 运行中每 30 分钟 tick），不接入 scheduler 定时任务系统——该系统任务唯一执行形态是跑 agent 会话，备份是纯本地操作不该过模型；恢复 builtin kind 等于重启刚退役的架构路径
- 到期判断零状态：扫备份目录最新文件时间戳 vs 配置频率间隔（文件名含时间戳，目录即真相，无需 lastFiredAt）
- 不做增量备份（YAGNI；zip 全量 + 轮换清理已控制体积）

### 恢复

- 数据中心备份列表：按分类查看已有备份（时间 / 大小）
- 「恢复」：选中一份恢复到原位，**恢复前自动先备份当前状态**（防恢复本身出错），失败即中止
- 「打开备份目录」：系统文件管理器直达
- 单文件级恢复本轮不做（后置）

## 数据中心「版本与备份」区块

只读状态 + 备份操作一体：

- **用户仓库**：是否 git 仓库 / 当前分支 / 未提交改动数（只读展示，提交仍走 agent）
- **影子安全网**：快照条数 / 最近快照时间 / 仓库体积
- **备份**：各分类当前状态（最近备份时间 / 份数）+ 开关与频率配置 + 「立即备份」 + 备份列表与恢复入口
- 降级：系统无 git 时 git 两区显示「未安装 git」，备份区不受影响

## 文件历史面板修复

1. **右侧顶部改为版本详情头**：选中版本时显示徽标（Agent/你/外部）+ 完整时间 + **完整消息（不截断换行展示）** + hash 短显 + 差异统计；左侧列表保持紧凑
2. **diff 改 hunk 模式**：每个差异块上下 3 行上下文，块间折叠条「⋯ 省略 N 行」点击展开；`lib/line-diff.ts` 的 LCS 核心不动，仅在输出层新增折叠结构

## 模块边界

| 模块 | 说明 |
|---|---|
| `electron/main/services/backup-service/`（新增） | 分类定义、zip 打包、调度检查、轮换清理、恢复；单文件 >300 行拆分 |
| settings 备份配置节 | settings.json 新增 `backup` 节（分类开关/频率/保留份数），走 settings-service |
| tipc backup 路由 | getBackupStatus / runBackup / listBackups / restoreBackup / openBackupDir |
| 数据中心页面 | 新「版本与备份」区块；git 状态查询复用 git-service |
| `components/FileHistoryPanel.tsx` 等 | 面板两处修复 |

## 错误处理 / 边界情况

- 备份失败：记录状态并 toast，不中断其他分类
- 磁盘满 / 权限错误：分类提示；备份目录所在盘剩余空间预检
- 恢复前预备份失败 → 中止恢复并提示
- git-missing：git 状态区降级提示，备份功能独立可用
- 备份进行中重复触发：同分类串行队列（沿用影子仓库的队列模式），跳过未完成的重入

## 未决问题

- zip 压缩等级（默认 standard，超大分类可后置调优）
- 数据中心是否加影子历史的全局浏览入口（本轮只展示状态数字）
