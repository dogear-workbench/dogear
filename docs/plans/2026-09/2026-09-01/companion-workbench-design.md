# 伴随工作台与执行可视化 设计

**日期**：2026-09-01
**状态**：已拍板，一期待写实施计划

## 背景

功能越加越多带来三个排布问题：① 固定 tab 平铺会挤占 tab 栏；② agent 的 Bash 由 pi-agent-core spawn + 输出 buffer 执行（`workspace-execution-env.ts` exec → inner.exec），**过程对用户不可见**，会话里只有事后工具块；③ 双屏下这些内容怎么摆、独立窗口和内嵌怎么共存。

讨论中确立的核心模型：**伴随工作台**。

## 目标

1. 建立「功能放哪」的判据体系，终结 tab/侧栏/窗口的纠结
2. 右侧栏升级为「伴随工作台」：面板集合 + 内嵌/窗口两形态容器，窗口可直接打开不经内嵌中转
3. 一期实现终端观察窗：agent 命令过程实时转播可见

## 架构

### 判据体系（两个正交维度）

- **伴随型**（内容随活动会话变化，离开会话无意义）vs **独立型**（内容自存在）
- **参照型**（看一眼核对，窄条够用）vs **沉浸型**（长时间读/操作，需要大空间）

| | 参照型 | 沉浸型 |
|---|---|---|
| **伴随型** | 右侧工作台（文件/附加/话题） | 右侧工作台可拖宽/弹窗（终端直播） |
| **独立型** | header 入口/徽章 | tab/独立窗口（笔记、数据中心） |

不看功能大小，看它是不是会话的附属。笔记/数据中心再大也是独立场景；终端流再窄也是会话的直播。

### 容器模型（四类）

| 容器 | 承载 | 形态 |
|------|------|------|
| 主窗口 | 会话场景：tab 系统 + 右侧伴随工作台 | 现状 |
| 功能页 | 数据中心、笔记（看数据/资产） | 已有双形态：tab 常驻 + hover 弹窗 |
| 伴随工作台 | 面板集合：文件/附加/话题/终端/未来浏览器操作 | **两形态：右侧栏 + 伴随工作台窗口** |
| 场景窗口 | 自选股等独立领域 | 保持 |

### 伴随工作台（本设计核心）

- **内嵌形态**：主窗口右侧栏（现状三 tab + 新终端 tab）
- **窗口形态**：一个「伴随工作台窗口」，内部 tab 与右侧栏同构，header 入口直接打开，**不经内嵌中转**；记住上次位置
- 两容器消费同一 store 数据，天然同步（TopicPanel 右栏/数据中心双入口同模式）；「当前看哪个会话」是容器本地状态，不跨窗共享
- **宽度**：自由拖拽，**每个伴随 tab 记住各自宽度**（终端 550px、文件 260px，切换自动恢复）；不做宽窄分档
- 双屏动线：主窗口纯会话，副屏开一个伴随工作台窗；不开全局布局编排器，各窗口独立记住位置（YAGNI）
- 选中**统一容器**（一个窗内切面板）而非每面板一窗：副屏一窗全装下，Alt+Tab 切换窗口数少，加面板自动多一个 tab

### 终端可视化：两步走（C 方案）

**一期：转播观察窗（只读）**
- 零 patch：pi-agent-core Bash 原生 `onUpdate` 流式回调（100ms 节流、累积输出快照），经 agent-loop `tool_execution_update` 事件、pi-harness-adapter `onAgentEvent` 已透传到 pi-session，只需在 pi-session 分流
- 主进程 terminal-stream 服务：按会话累积环形缓冲 + 广播增量事件（快照前缀 diff 出尾部增量）
- 终端面板：**按命令分组的滚动卡片流 + ANSI 颜色渲染**（onUpdate 给的是累积快照非字节流，命令卡片天然支持重设；xterm.js 全屏终端心智留给二期 PTY）
- **一个会话 = 一条命令流**（命令顺序 append），无多实例
- 两种焦点模式：内嵌 tab 跟随主窗口活动会话；工作台窗口可**固定**盯某会话（主窗口跟 A 聊，副屏窗盯子会话 B 执行）
- 打开面板时先 RPC 拉缓冲历史，再订阅增量

**二期：PTY 共享终端（可介入）**——node-pty，用户可在 agent 命令间隙自己敲、共享 cd/环境、agent 可另起终端；面板内部加**实例 tab，放面板底部**；重写 Bash 执行模型（输出边界/exit code/超时），风险高，一期跑顺确认真需求后再做

**浏览器/电脑操作可视化**：执行可视化家族后续成员，同结构——一期「一会话一条操作流」，将来多实例也是面板底部 tab。

### 排除的选项及原因

- **同窗口跨双屏拉伸**：两屏 DPI 缩放不一致（150%/100% 常见）时 Chromium 跨屏渲染模糊、popup 定位偏移，基本无解；双屏 = 第二独立窗口
- **底部 dock 放终端**：破坏从上往下阅读会话的动线，用户明确偏好左右排布
- **右侧栏宽窄分档**：多余设计，自由拖拽 + 各 tab 记住宽度更简单
- **一键双屏布局（布局编排器）**：要管理窗口摆位/恢复/异常，复杂度高收益小；双屏工作流稳定，逐窗口记住位置、开工点两下可接受
- **功能页收进右侧栏**：沉浸型独立内容塞右侧会把会话主体挤没
- **独立窗口通信顾虑**：非新问题，既有纪律已覆盖（窗口只跟主进程对话，真相源 = 主进程服务 + 盘上 JSON，visibilitychange 管轮询，常态 2-3 窗口每窗口 50-150MB）

## 模块边界（一期）

**主进程**：
- pi-session Bash 流式回调（pi-agent-core 勘查，可能 bun patch）
- terminal-stream 服务：按会话环形缓冲 + 增量广播 + 历史 RPC
- 伴随工作台窗口创建（照抄数据中心/自选股窗口模式，记住位置）

**前端**：
- 右侧栏：宽度拖拽 + 各 tab 宽度持久化；新增终端 tab
- 终端面板组件（可移植：数据走 store + IPC，不依赖主窗口上下文）
- 伴随工作台窗口页面（复用右侧栏面板组件）
- header 工作台窗口入口

**store**：
- 终端流 store：订阅广播 + 按需拉历史，消费端渲染

**不动**：数据中心/笔记/设置形态；右侧栏现有三 tab 功能；pi-agent-core Bash 执行语义。

## 数据流

agent Bash 执行 → onUpdate（100ms 节流累积快照）→ agent-loop `tool_execution_update` 事件 → pi-session 分流 → 主进程 terminal-stream 环形缓冲 + 前缀 diff 出尾部增量广播 →（右侧栏终端 tab | 工作台窗口终端面板）订阅渲染。窗口后开先 RPC 拉缓冲对齐再收增量。

## 错误处理 / 边界情况

- 缓冲上限：每会话环形截断（约 1MB / 5000 行，实施时定），会话销毁回收缓冲
- 二进制输出、超长行、控制序列异常的容错（防渲染卡死）
- 终端 tab 空态（该会话还没跑过命令）
- 流量节流：chunk 到达即推 vs 批推，实施时定参数
- 无容器挂载终端面板时不必订阅渲染，缓冲在主进程不丢
